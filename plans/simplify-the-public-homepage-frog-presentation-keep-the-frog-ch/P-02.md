# Add focused homepage navigation and accessibility regression evidence

## Objective

Add a compact automated regression boundary for the simplified public
homepage. Prove that the three frog images remain the primary named content,
the retired descriptive sections stay absent, and the market-browsing and
direct-price links remain semantic, keyboard-operable, and usable at narrow
and wide viewports. Cover responsive containment, reduced-motion behavior, and
representative automated accessibility checks without exercising or changing
backend behavior.

This Task requires approval because it adds project-level regression coverage
for the public landing page and may extend existing test support.

## Acceptance Criteria

- A focused homepage component or DOM test asserts one named Bramble image,
  one named Cooper image, and one named Pip image, with no duplicate
  character-card rendering.
- Focused negative assertions cover the retired marketing contract: the
  kingdom eyebrow, slogan, explanatory paragraph, all three value headings,
  tavern introduction, character roles, and biographies are absent. The test
  does not depend on a full-page snapshot or exact Tailwind class strings.
- Tests locate `마켓 둘러보기` and `직구가 계산하기` by accessible role and
  name, assert their `/markets/muk` and `/direct-price` destinations, and prove
  both can receive focus and be activated using only the keyboard.
- Semantic assertions cover one main landmark, a concise accessible page name,
  meaningful names for the three content images, and no duplicate
  announcements from decorative layers.
- An automated accessibility check over the rendered homepage reports no
  serious violations. Color-independent focus indication and a logical source
  and tab order for the two primary links are asserted directly where an
  automated rule cannot prove them.
- Browser-level or equivalent layout checks cover at least a 320px-wide mobile
  viewport and a representative desktop viewport. They assert no horizontal
  document overflow, all three character images intersect the visible content
  area, and both primary links are visible, unobscured, and operable beneath
  the sticky public navigation.
- A reduced-motion check proves the revised page's remaining `wf-*` entrance,
  character, glow, and dust effects do not animate when
  `prefers-reduced-motion: reduce` is active. The check is limited to classes
  actually retained by the page.
- Network isolation or request mocking prevents the shared navigation's public
  market-list request from making homepage assertions depend on a live
  backend. Tests do not add, alter, or validate an API response contract as
  part of this presentation change.
- The added coverage is deterministic and does not require credentials,
  production data, a persistent manually started server, or changes to
  existing catalog/market fixtures.
- `npm test`, the focused homepage browser/layout check, and
  `npm run build` pass, and the commands and outcomes are recorded in
  Implementer Verification.

## Constraints

- Do not weaken existing catalog, market, facet, price-history, or
  direct-price tests to make the homepage coverage pass.
- Do not use screenshot approval alone as evidence for semantics, navigation,
  or responsive containment.
- Do not make tests depend on a live backend, production market data,
  credentials, or production writes.
- Do not change API clients, generated types, backend routes, or response
  fixtures under the guise of homepage test setup.
- Do not add tests for unrelated destination-page behavior; this boundary
  proves that the homepage exposes working navigation to those routes.

## Context

The repository has Node/Testing Library component coverage with `axe-core` and
Playwright coverage for catalog and per-market pages, but no focused homepage
regression file. The shared public shell includes a client-side market-list
request, so homepage tests need to isolate that incidental request even though
the homepage itself is static. The existing test and browser infrastructure
can cover user-observable semantics and layout without introducing a backend
contract change.
