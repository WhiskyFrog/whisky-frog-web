# Simplify the homepage into a frog-first functional presentation

## Objective

Revise the public `/` page so its main content is one responsive composition
of the existing Bramble, Cooper, and Pip imagery with clear links to market
browsing and direct-price calculation. Remove the homepage's marketing
eyebrow, slogan, explanatory introduction, value cards, tavern introduction,
character roles, and character biographies. Reuse the public shell and local
visual language, retain concise accessible page and image identification, and
do not change data access, destination pages, backend behavior, or API
contracts.

This Task requires approval because it changes the primary public landing page
and removes visible content.

## Acceptance Criteria

- `/` presents the existing Bramble, Cooper, and Pip preview assets together
  as the visually dominant main content. Each character is rendered once in
  the primary composition; no second biography/card presentation remains.
- The homepage no longer renders the `Whisky Kingdom` eyebrow, the
  `Good whisky, good friends, good time.` slogan, the introductory kingdom
  paragraph, the three `Good Whisky`/`Good Friends`/`Good Time` value cards,
  the `Royal Tavern` introduction, `오늘의 한 잔을 찾는 세 친구`, character
  roles, or character biographies. No new promotional paragraph or value
  proposition replaces them.
- The shared `Whisky Frog` home link remains intact, and the page retains one
  concise heading or equivalent accessible document name. Brand naming is not
  expanded into descriptive marketing copy.
- A clearly visible link named `마켓 둘러보기` still points to
  `/markets/muk`, and a clearly visible link named `직구가 계산하기` still
  points to `/direct-price`. Both are native links, occur in logical source
  order, expose visible keyboard focus, and remain distinguishable without
  relying only on color.
- Character alternatives retain meaningful names for screen-reader users.
  Decorative glow, dust, framing, and background elements remain ignored by
  the accessibility tree and do not duplicate the character announcements.
- At representative 320px mobile, tablet, and desktop widths, all three
  characters remain recognizable, the main content has no unintended
  horizontal overflow, neither functional link is covered or clipped, and
  the sticky navigation does not obscure the primary content.
- Existing character motion may be retained or simplified, but the
  `prefers-reduced-motion: reduce` path disables every homepage entrance,
  character, glow, and dust animation still used by the revised composition.
  The page remains understandable with motion disabled.
- The implementation reuses the existing public character assets, shared
  `HomeShell`/`TopNav`, palette, and link treatment. It does not introduce a
  new asset dependency or change unrelated public-page styling.
- No API client, generated API type, backend route, environment variable,
  market/direct-price page behavior, shared market fetch, or price-calculation
  behavior changes.
- `npx tsc --noEmit` and `npm run build` pass after the page revision.

## Constraints

- Do not add replacement brand lore, slogans, value propositions, character
  roles, character biographies, or another text-heavy homepage section.
- Do not delete or replace the Bramble, Cooper, or Pip preview assets.
- Do not change `TopNav` market loading, authentication behavior, the market
  route, the direct-price route, backend code, API requests, or generated API
  contracts.
- Do not make the imagery a CSS background when doing so would remove its
  semantic image name or make the character content inaccessible.
- Do not require a hover interaction, animation, or wide viewport to reveal
  either functional destination.
- Keep the implementation confined to homepage presentation and directly
  necessary local styling; do not redesign the shared public shell.

## Context

The current `app/(home)/page.tsx` renders a text-heavy two-column hero, three
value cards, and a second three-card character section. The visual hero already
uses the three preview PNGs and individual `wf-*` motion classes, while
`app/globals.css` has a reduced-motion rule for those effects. The same page
already exposes the two required destinations. The desired change is therefore
a deletion and recomposition of static homepage content, not a new feature or
data integration.
