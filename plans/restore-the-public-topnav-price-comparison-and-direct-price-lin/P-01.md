# Restore the public TopNav destinations at every viewport

## Objective

Correct the shared public `TopNav` so its `가격 비교` and `직구가 계산` links
are visible, semantic, keyboard-operable, and contained at every supported
viewport, including 320px mobile. Introduce the smallest responsive
recomposition needed to fit the existing home, market, destination, and
administrator controls without horizontal page overflow, while preserving the
current destinations and all existing navigation behavior. Add focused DOM
and browser regression evidence, including a recorded reproduction of the
pre-correction narrow-width failure.

This Task requires approval because it changes the shared navigation rendered
on every public page.

## Acceptance Criteria

- Inside the public navigation landmark, one native link named `가격 비교`
  points to `/products` and one native link named `직구가 계산` points to
  `/direct-price`. Neither link uses responsive `display: none`, conditional
  rendering, a hover-only submenu, or an inaccessible icon-only replacement at
  any supported width.
- At real 320px, representative intermediate, and 1280px browser viewports,
  both required links are visible, have non-zero boxes wholly within the
  viewport, can receive visible keyboard focus, and activate their existing
  destinations.
- At each exercised viewport,
  `document.documentElement.scrollWidth <=
  document.documentElement.clientWidth`, the navigation's own scroll width
  does not exceed its client width, and no required navigation control is
  clipped or covered.
- The responsive layout keeps the `Whisky Frog` home link, market control, and
  administrator action available. The market menu remains usable, and the
  administrator action retains its existing authentication/login-modal
  behavior.
- If the narrow navigation becomes taller or wraps, the sticky shell uses
  content-driven sizing and the first public main content remains visible and
  reachable rather than being obscured beneath it.
- The correction preserves current colors, typography, semantic `<nav>`,
  native anchors, focus treatment, public-market fetch, and route destinations.
  It does not create a separate mobile navigation data source or duplicate the
  destination links in page content as a workaround.
- A focused assertion is shown to fail against the pre-correction behavior
  because the navigation-scoped destination links are hidden at 320px. The
  same assertion passes against the completed correction, and both outcomes
  are recorded in Implementer Verification.
- Focused component or DOM coverage scopes the link role/name/href assertions
  to `TopNav`; it cannot pass by finding similarly named homepage content.
- The existing serverless homepage Playwright boundary covers at least 320px
  and 1280px, measures document and navigation containment, and asserts the two
  navigation-scoped links are visible and unobscured. It uses mocked incidental
  market loading and does not depend on a live backend or persistent server.
- `npm test`, `npm run e2e:homepage`, and `npm run build` pass after the
  correction, with commands and outcomes recorded in Implementer Verification.

## Constraints

- Do not remove, rename, or redirect the home, market, price-comparison,
  direct-price, or administrator controls.
- Do not solve the 320px layout by enabling horizontal page or navigation
  scrolling, clipping text, hiding another required control, or requiring
  hover to reveal either destination.
- Do not change public-market API behavior, authentication, `LoginModal`,
  destination pages, backend code, API clients, generated types, or
  environment configuration.
- Do not make assertions depend on exact Tailwind class strings or screenshots
  alone; verify accessible links and computed layout.
- Do not require credentials, production data, a live backend, or a manually
  started persistent server.

## Context

`app/components/TopNav.tsx` currently renders the correct native anchors and
destinations, but both have `hidden sm:block`, so their computed display is
`none` below the 640px breakpoint. The same component fixes the navigation to
one `h-16` row containing the brand/market/link cluster and administrator
button, leaving no explicit 320px composition once the links are restored.
`app/(home)/HomeShell.tsx` shares this component across the public route group.
The existing `e2e/homepage.spec.ts` already has serverless 320px and 1280px
projects and document-overflow measurement, but its destination locators target
homepage calls to action rather than the two links inside `TopNav`.
